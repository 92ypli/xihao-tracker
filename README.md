# 喜好跟踪

每天收盘后自动抓数据、算区间、生成页面、推送摘要。全部跑在 GitHub 上，不需要服务器，不需要备案，不需要任何电脑常开。

---

## 跟踪范围

- **A 股**：东方财富「游戏Ⅱ」板块全部成分股（24 只），带估值分位和加减仓区间
- **港股**：16 只主要游戏股（腾讯、网易、心动、中手游、IGG、金山软件、哔哩哔哩……），带价格分位和区间
- **催化剂**：版号公示明细、产品管线（人工维护）、公告与报告里的近期动态、财报窗口
- **产品档案**：每家公司的代表产品、在测产品、上线时间、**TapTap 评分与好评率**（人工填清单，口碑自动抓）

## 它每天产出什么

1. **一条推送**（钉钉 / 企业微信 / Server酱，配了才发）——板块概况、低位区名单、重点标的区间、版号命中、当日新消息
2. **一个网页**（GitHub Pages）——A 股 + 港股完整列表、单只详情、催化剂面板、公告、报告
3. **一份归档**——`reports/YYYY-MM-DD.md` 和 `data/history.jsonl`

第三项别小看。`history.jsonl` 每天记录每只标的的估值分位和当时算出的区间，攒三个月就是一套现成的复盘素材，可以直接验证这套区间判断的命中率。

## 部署步骤

### 第 0 步：先确认数据源通不通

这一步能帮你省掉一整天。

GitHub 的服务器在海外，国内财经接口对海外 IP 的通达性是个变量。先把代码推上去，然后：

**Actions → 数据源自检 → Run workflow**

跑完会打印一张表，每个接口一行，标明耗时和结果。如果关键接口（板块成分股、估值历史）显示 `FAIL`，说明这条路走不通，直接跳到文末「如果海外节点抓不到」。

### 第 1 步：建仓库

GitHub → New repository → 名字随意（比如 `xihao-tracker`）→ 选 **Private** 或 Public 都行 → **不要**勾 Add README / .gitignore / license。

### 第 2 步：推代码

```powershell
cd <项目所在目录>

# 身份（没配过就要配一次）
& "C:\Program Files\Git\cmd\git.exe" config --global user.email "你的GitHub邮箱"

# 提交并推送
& "C:\Program Files\Git\cmd\git.exe" add .
& "C:\Program Files\Git\cmd\git.exe" commit -m "init: 喜好跟踪"
& "C:\Program Files\Git\cmd\git.exe" remote add origin git@github.com:你的用户名/xihao-tracker.git
& "C:\Program Files\Git\cmd\git.exe" push -u origin main
```

注意：这台机器 PATH 里的 `git` 是 2013 年的 1.8.1，连不上 GitHub。上面用的是完整路径指向 2.55.0。一劳永逸的修法是把 `C:\Program Files\Git\cmd` 移到环境变量 Path 的最前面。

### 第 3 步：开启 Pages

仓库 → **Settings → Pages**：

| 项 | 值 |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` |
| Folder | `/docs` |

保存后，你的页面地址是：

```
https://你的用户名.github.io/xihao-tracker/
```

第一次要等一两分钟才生效。在手机浏览器打开，用「添加到主屏幕」，之后就是独立图标、全屏打开。

### 第 4 步：授权 Actions 写入

仓库 → **Settings → Actions → General** → 拉到最下面 → Workflow permissions → 选 **Read and write permissions** → Save。

不设这一步，定时任务跑完没法把结果提交回来。

### 第 5 步：配推送（可选但推荐）

因为网页在国内的稳定性不保证，推送才是主力通道。

**钉钉**：建一个只有自己的群 → 群设置 → 智能群助手 → 添加机器人 → 自定义 → 复制 Webhook 地址

**企业微信**：建群 → 群机器人 → 添加 → 复制 Webhook 地址

然后仓库 → **Settings → Secrets and variables → Actions → New repository secret**，名字用下面之一：

| Secret 名 | 说明 |
|---|---|
| `PAGE_PASSWORD` | **页面的解密密码**，见下一节 |
| `DINGTALK_WEBHOOK` | 钉钉机器人完整 Webhook 地址 |
| `WECOM_WEBHOOK` | 企业微信机器人完整 Webhook 地址 |
| `SERVERCHAN_KEY` | Server酱的 SendKey |

配几个都行，会同时发。一个都不配也能跑，只是不推送。

钉钉机器人有安全设置，如果选了「自定义关键词」，把关键词设成 `喜好跟踪`，不然消息会被拒。

### 第 5.5 步：设置页面密码（强烈建议）

`PAGE_PASSWORD` 不设的话，页面会是「还没有配置密码」的占位页，什么数据都不显示。这是故意的——代码里写死了：CI 环境下没密码就不发布真实数据。

设好之后跑一次每日任务，页面就会用这个密码加密生成。打开时要求输入密码，输对了才解密渲染。

**加密是怎么做的：**

```
密码 --PBKDF2-SHA256(25 万次迭代)--> 密钥 --AES-256-GCM--> 密文
```

页面里只有 base64 密文和盐、初始向量，没有任何明文。拿不到密码，就算把 HTML 下载下来也只是一堆乱码。

**关于密码的几件事：**

- 密码只存在 GitHub Secrets 和你手机的浏览器里，**不上传、不写进代码**
- 手机上输一次会记住，之后自动进入；页脚有「锁定本设备」可以清掉
- **忘了不影响任何东西**，换一个密码、重跑一次任务就行，历史数据不受影响
- 别用 `123456` 这种，加密强度取决于密码强度

### 第 5.6 步：仓库里不放明文

因为仓库是公开的，`data/latest.json`、`data/history.jsonl`、`reports/` 都已经加进 `.gitignore`，**不再提交**。

仓库里只会留下一样数据产物：`docs/index.html`，而它是加密的。

日期归档走 `data/history.enc`——每天一行加密记录，用于以后回测。想看的时候：

```bash
PAGE_PASSWORD=你的密码 node scripts/decrypt.mjs           # 看总览
PAGE_PASSWORD=你的密码 node scripts/decrypt.mjs 002555    # 看单只的区间变化
```

### 第 6 步：先手动跑一次

**Actions → 每日任务 → Run workflow**。

跑完检查三件事：

1. Actions 日志里出现 24 行标的表格
2. 仓库里多了 `data/`、`reports/`、`docs/`
3. 手机收到推送（如果配了）

都没问题，之后每天北京时间 15:30 会自动跑。

## 怎么改

改跟踪范围、重点票、区间参数，只需要动 `src/config.mjs`：

```js
export const CONFIG = {
  board: { code: "BK1046", name: "游戏", industryCode: 1046 },
  focus: ["002555", "002517"],          // 重点跟踪的标的
  hkFocus: ["09999", "02400"],          // 港股重点
  valuation: {
    lookbackYears: 5,                    // A股估值分位回看几年
    hkLookbackYears: 5,                  // 港股价格分位回看几年
    bands: { addLow: 15, addHigh: 30, trimLow: 70, trimHigh: 85 },
  },
};
```

港股清单在同一个文件的 `hk` 数组里，每项是 `{ code, name, aliases }`。`aliases` 用于匹配版号公示里的公司名，比如金山软件的子公司「西山居」就靠这个字段匹配。

可以从清单里删掉不关心的港股，也可以加新的——只要东财有该港股代码就能取到数据。

换板块改 `board.code`（东财行业板块代码）和 `industryCode`（报告的行业代码）。

### 产品管线要自己填

**免费数据源拿不到「某款游戏什么时候测试、什么时候上线」。** 任何声称能自动做到这件事的方案都是不可靠的——要么数据是付费的，要么是在编。

所以这块设计成人工维护：改 `config/pipeline.json`，工具负责排序、标注临近、进日报和推送。

```json
{
  "items": [
    {
      "company": "002558",
      "companyName": "巨人网络",
      "product": "《原始征途》手游",
      "stage": "定档",
      "expectedDate": "2026-10",
      "note": "已获版号，等待公测"
    }
  ]
}
```

`stage` 建议用：首曝 / 预约 / 测试 / 定档 / 上线 / 已上线。`expectedDate` 支持 `YYYY-MM`（按当月 1 号算）或 `YYYY-MM-DD`，不确定就留空，会被排到最后。

**这个文件我故意留空了。** 我没有可靠的未来上线时间数据源，编几条进去只会误导你。填两条真实的比填二十条臆测的有用得多。

## 产品档案：口碑全部自动抓取

个股详情里会展开这家公司的**代表产品**和**在测产品**，带上线时间、预期时间倒计时，以及 **TapTap 评分**。

清单在 `config/profiles.json` 里，**产品名称已经全部填好**（40 家公司 82 个产品）。TapTap 的 id 不用你找——程序会自己去搜。

### 全自动的三步

```
1. 按产品名去 Bing 站内搜索，找到 TapTap 的 /app/<id>
2. 用这个 id 抓详情的评分、好评率、评价数、上线日期、状态标签
3. 用 TapTap 的「厂商」字段和公司名比对，核对归属对不对
```

第 1 步的结果会缓存到 `data/taptap-cache.json`，所以**只有第一次跑得慢**（约 80 秒），之后每天直接按已知 id 抓，几秒钟的事。

搜不到的产品会记下来，**30 天后自动重试**，不会每天白跑一遍。

```json
"02400": {
  "name": "心动公司",
  "aliases": ["心动", "XD"],
  "products": [
    { "name": "心动小镇", "type": "自研", "status": "运营中", "taptap": "", "note": "模拟经营，公司近年自研主力" }
  ]
}
```

`taptap` 字段留空就会自动搜索；如果你想指定，填 id 或完整链接都行（地址栏 `/app/` 后面那串数字）。
`aliases` 是给归属核对用的——TapTap 上显示的是子公司或工作室名，比如金山软件要写 `西山居`、吉比特要写 `雷霆`。

### 自动抓到的字段

| 字段 | 来源 |
|---|---|
| 评分（满分 10） | `stat.rating.score` |
| 好评率 | 4~5 星评价占比，从 `stat.vote_info` 算 |
| 评价数 | `stat.review_count` |
| 关注数 | `stat.fans_count` |
| 状态标签 | `title_labels`，直接标出「测试」「先行服」「预约」 |
| 上线日期 | 详情页的发行信息 |
| 品类标签 | `tags` |
| 厂商 | `information` 里的「厂商 / 发行 / 供应商」 |
| **预约人数** | `stat.reserve_count`，每日更新 |
| **关注人数** | `stat.fans_count`，每日更新 |

### 测试效果是逐日跟踪的

预约人数和关注数是**上线前最能预示成绩的两个数字**，而且每天都在变。

程序每天把每个产品的这四个数存进 `data/taptap-trend.json`（保留最近 30 次），页面上会直接显示变化：

```
仙境传说 RO2   测试中   评分 7.7 · 好评 68.2% · 预约 24.1万 · 关注 25.0万
                        较 2026-09-09：预约 +3,240、关注 +1,180、评分 +0.1
```

这样一款游戏从测试到上线，热度是往上走还是往下走，一眼能看出来。

### 归属核对：自动发现可能填错的产品

程序会把 TapTap 上的厂商名和你写的公司名比对，**对不上的会在页面上标一个 ⚠**。

目前 82 个产品里，10 个标了 ⚠。**大部分不是错误，而是子公司或工作室名**——比如：

| 产品 | TapTap 显示 | 说明 |
|---|---|---|
| 幻塔 | Hotta Studio | 完美世界旗下工作室，归属正确 |
| 永劫无间手游 | 24 Entertainment | 网易旗下工作室，归属正确 |
| 王国纪元 | 天盟数码 | IGG 的关联主体，归属正确 |
| 三国志2017 | 天上友嘉 Youkia | 凯撒文化收购的公司，归属正确 |

但**也有真需要复核的**，比如《全民奇迹》TapTap 显示厂商是「腾讯」、《原始传奇》显示「贪玩游戏」——这两条可能是版本选错或归属写错。

所以 ⚠ 不是"错"，是"这里值得你看一眼"。这比我自己拍胸脯说"填对了"有用。

### 口碑数据里没有我的主观判断

评分、好评率、评价数、状态标签都是接口给的客观数据。

「这游戏好不好玩」「付费设计有没有争议」这类判断，**我没有写进去**。凭印象写出来的评价你没法验证，还可能已经过时——而 TapTap 的评分本身就是行业里公信力最高的公开口碑指标，它比我可靠。

`note` 字段我填的是**品类和运营模式这类可核对的事实**（比如「赛季制刷宝 ARPG」「公司现金流基石」），不是评价。

## 加仓价 / 减仓价是怎么算的

**A 股和港股用的是两套口径**，页面上会标出来，两者不可直接比较。

### A 股：估值分位

核心假设：盈利预期不变时，估值分位决定合理价格。

```
目标价 = 现价 × (历史某分位的估值 / 当前估值)
```

PE、PB、PS 三个口径各算一遍再加权（PB 权重最高，因为这类标的盈利周期波动大，PE 容易失真）。

### 港股：价格分位

**港股拿不到免费的历史估值数据**，而且港股游戏股里亏损公司占比很高，PE 分位本身也不成立。所以改用价格分位：

```
加仓价 = 近 5 年价格的 30 分位
减仓价 = 近 5 年价格的 70 分位
综合分位 = 现价在近 5 年价格分布中的分位
```

价格是前复权序列，口径一致、可复现、可回测。

### 共同的分区规则

- 低于 30% → **加仓区**
- 30% 到 70% → **持有区**
- 高于 70% → **减仓区**

### 两层护栏

第一层，**2%/98% 截尾**。历史盈利低谷期的极端 PE 会把分位带歪——实测中曾出现减仓价算到现价的 4 倍，就是这个问题。

第二层，**合理性剔除**。某个口径反推的减仓价超过现价 2.2 倍、或加仓价低于现价 0.45 倍，说明这个口径在当前不适用，直接弃用，权重分给其余口径。三个口径都不合格时显示「数据不足」，而不是硬给一个数。

### 失效条件

区间只在基本面没变的前提下成立。页面上会列出触发条件：

- PE(TTM) 转负
- 跌破年线
- 机构近 3 个月下调盈利预测
- 股价接近近 3 年最低（港股口径，需先确认是估值问题还是基本面问题）

触发任一条，就不要按价格机械加减仓。

## 数据源

| 内容 | 来源 | A股 | 港股 | 成本 |
|---|---|---|---|---|
| 实时行情 | 东方财富 / 腾讯 | ✅ | ✅ | 免费 |
| 日线历史（前复权） | 东方财富 / 腾讯 | ✅ | ✅ | 免费 |
| 估值历史（PE/PB/PS，5 年日频） | 东方财富数据中心 | ✅ | ❌ | 免费 |
| 公告 | 东方财富 | ✅ | ❌ | 免费 |
| 报告标题与盈利预测 | 东方财富 | ✅ | ❌ | 免费（正文需付费） |
| 版号审批明细 | 国家新闻出版署 | ✅ | — | 免费 |
| 产品上线时间 | 无 | ❌ | ❌ | 需人工维护 |

### 已知限制

- **港股没有估值历史、公告、报告**，所以港股只有行情和价格分位。
- **版号公示日期在日程里是经验规律**（取每月 22 日）；但**实际公示结果是真实抓取的**，含产品名、出版单位、运营单位、批准时间。
- **版号匹配靠公司名关键词**。出版单位和运营单位经常是子公司或工作室，`config/pipeline.json` 旁边的 `CONFIG.license.extraAliases` 里可以补关键词。匹配到的主体和字段会在页面上标出来，方便你核对。
- **报告只有标题和盈利预测，没有正文。**
- **没有接入流水类数据**（第三方数据服务都是付费的）。
- **网页在国内的访问稳定性一般**，所以推送是主通道。
- GitHub 的定时任务在高峰期可能延迟十几分钟，偶尔漏跑。

## 本地开发

不用推代码就能跑全流程，需要 Node 20 以上：

```bash
npm run probe    # 数据源自检
npm run daily    # 抓取 + 生成 docs/ + reports/ + data/（不设密码就是明文，方便调试）
npm run preview  # 只看终端表格

# 带密码跑（和线上一致）
PAGE_PASSWORD=你的密码 npm run daily
```

项目零依赖，不用 `npm install`。改完 `src/` 之后用 `npm run daily` 在本地验证，比等 GitHub 跑一次快得多。

**本地不设 `PAGE_PASSWORD` 会生成明文页面**——这是刻意的，方便调试。但只有 CI 环境（`CI=true`）下才会写占位页，所以本地调试不会误发布明文。
